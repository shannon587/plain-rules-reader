Plain Rules Reader: App Map

A take-home guide to what was built, where each part lives, and one practice worth reusing. Snapshot of the code at commit f0cad43; the map can drift as the code changes.

What it is, in plain language

One small Python program, rules_reader.py. You hand it a competition or program rules page: a web address, a saved file, or pasted text. It washes a web page down to its readable words, runs four finders over the text (description, deadline, cost, eligibility), and prints four labeled answers in short plain sentences. A finder that comes back empty becomes an honest line: I could not find it in this page. Nothing is stored, and there is no AI model and no key: the reading is careful pattern matching, standard library only.

One action, end to end

The same path in words: input arrives at read_source, page markup is cleaned by html_to_text, the four finders search the text, and plain_answers lays out the result.

The route: follow the fee answer

This is a reference route for reading the code later. The walkthrough with Shannon is scheduled for her October 26 presentation.

Stop 1: where a page comes in

rules_reader.py, functions read_source and fetch_url. A web address is fetched here; a file is read here; pasted text enters through main. Every failure leaves through one plain error line, never a crash.

Stop 2: the finder that caught the fee

rules_reader.py, function find_cost, with FEE_PATTERNS and FREE_SIGNALS just above it. It decides free or fee sentence by sentence: an amount only counts as a fee when the word fee lives in the same sentence. That is why the FC2 page's $15,000 prize is not reported as the cost, and its $25 submission fee is.

Stop 3: where the four lines are laid out

rules_reader.py, function plain_answers, with LABELS and NOT_FOUND above it. Fixed label order, dates written out in full, the page's own words quoted as evidence, and an empty finder becomes the not-found line.

The proof for stop 2 lives in tests/test_rules_reader.py, check Fc2PrizesTest.test_cost_is_the_fee, run against the real saved FC2 page in tests/fixtures/.

To change this, start here

  • The words of the answers: LABELS and NOT_FOUND in rules_reader.py.
  • What counts as free or as a fee: FREE_SIGNALS and FEE_PATTERNS in rules_reader.py.
  • Which date shapes are recognized: DATE_RE and plain_date in rules_reader.py.
  • What counts as eligibility wording: ELIGIBILITY_STRONG and ELIGIBILITY_WORDS in rules_reader.py.

A practice to reuse

Write the check before you trust the answer. The product requirements (prd.md, Features and Behavior) said that on a page charging a fee, the cost line must name that fee. The automated check built on that sentence, run against the real FC2 page, caught the first version of the tool answering with the $15,000 prize instead of the $25 fee. The finder was rebuilt, and the same check now passes. A written, checkable criterion, tested against a real page, caught a wrong answer that looked right. That works on any project, with any agent.
